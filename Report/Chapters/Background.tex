\section{Background}\label{sec:background} % 2
This section begins by introducing the theoretical foundations on which the formalisation is based, then following~\citet{abs-2106-11818} in the present of the full \pill{} calculus, including processes, types, typing, environments / hyperenvironments, and judgements, then restrict attention to the multiplicative fragment \pimll{} when discussing operational semantics. 

Following~\citet{abs-2106-11818}, we use \hl{$\thl{blue}$} to highlight types and \hl{$\phl{red}$} for process terms throughout this thesis.

% subsection 2.1
\subsection{Classical linear logic, CLL}\label{subsec:CLL}
Linear logic~\citep{G87} is a refinement of classical and intuitionistic logic. In contrast to these systems, where assumptions can be duplicated or discarded freely, linear logic controls the use of structural rules such as weakening and contraction, thereby giving formulas a resource-sensitive interpretation~\cite{sep-linear-logic}. In this thesis, we work in the classical presentation of linear logic, where sequents are symmetric and duality replaces the distinction between assumptions and conclusions.

The multiplicative fragment forms the core of the system and includes the tensor connective {$\thl{A \tensor B}$} and its dual {$\thl{A \parr B}$}, together with the corresponding units {$\thl{1}$} and {$\thl{\bot}$}. These connectives capture composition and interaction of resources.

Intuitively, {$\thl{A \tensor B}$} describes the composition of two independent resources, while {$\thl{A \parr B}$} captures their dual form of interaction. Under a process interpretation, {$\thl{A \tensor B}$} can be read as producing a value of type {$\thl{A}$} and continuing as {$\thl{B}$}, whereas {$\thl{A \parr B}$} corresponds to receiving a value of type {$\thl{A}$} and proceeding as {$\thl{B}$}. The units {$\thl{1}$} and {$\thl{\bot}$} represent the absence of further output and input, respectively.
A simplified presentation of these rules is given below:
\begin{highlight}
\begin{figure}[h]
  \[
  \infer[\rlabel{\rname{$1$}}{rule:ll-one}]
    {\,\vdash \thl{1}\,}{}
  \qquad\qquad
  \infer[\rlabel{\rname{$\bot$}}{rule:ll-bot}]
    {\,\vdash \thl{\Gamma}, \thl{\bot}\,}
    {\,\vdash \thl{\Gamma}\,}
  \qquad\qquad
  \infer[\rlabel{\rname{$\tensor$}}{rule:ll-tensor}]
    {\,\vdash \thl{\Gamma}, \thl{\Delta}, \thl{A\tensor B}\,}
    {\,\vdash \thl{\Gamma}, \thl{A} \quad \vdash \thl{\Delta}, \thl{B}\,}
  \qquad\qquad
  \infer[\rlabel{\rname{$\parr$}}{rule:ll-parr}]
    {\,\vdash \thl{\Gamma}, \thl{A \parr B}\,}
    {\,\vdash \thl{\Gamma}, \thl{A}, \thl{B}\,}
  \]
\end{figure}
\end{highlight} 

Here \cref{rule:ll-tensor} presents a simplified form of the tensor rule from classical linear logic. In general, the tensor connective {$\thl{A \tensor B}$} combines two independent derivations. It requires a proof of {$\thl{A}$} and a proof of {$\thl{B}$}, each obtained from disjoint contexts, and produces a proof of the composite resource {$\thl{A \tensor B}$}. Intuitively, this corresponds to combining two independent resources into a single composite resource, and can be read  as producing a value of type {$\thl{A}$} and then continuing as {$\thl{B}$}.

The unit rule \cref{rule:ll-one} introduces the unit {$\thl{1}$}, which represents the absence of further obligations. It can be understood as an \emph{empty output}, corresponding to a computation that performs no further interaction, and serves as the neutral element of tensor.

Dually, \cref{rule:ll-parr,rule:ll-bot} describe the behavior of the connective {$\thl{A \parr B}$} and its unit {$\thl{\bot}$}. The~\ref{rule:ll-parr} rule combines resources within a single context, reflecting a form of interaction where both components are made available to the surrounding context. From an operational perspective, this corresponds to interacting with an input of type {$\thl{A}$} while continuing as {$\thl{B}$}. The unit {$\thl{\bot}$} represents the absence of further input, acting as an \emph{empty input} and serving as the dual neutral element. 

For example, two independent instances of the unit {$\thl{1}$} can be introduced by the~\ref{rule:ll-one} rule and combined via the~\ref{rule:ll-tensor} rule to derive {$\thl{1 \tensor 1}$}. In this case the surrounding context $\thl{\Gamma}$ and $\thl{\Delta}$ are empty:
\begin{highlight}
\[
  \infer[\tensor]
    {\,\vdash \thl{1 \tensor 1}\,}
    {
      \infer[\textit{$1$}]{\,\vdash \thl{1}\,}{}
      \quad
      \infer[\textsc{1}]{\,\vdash \thl{1}\,}{}
    }
\]
\end{highlight}

Here each leaf introduces one resource independently, and the tensor rule combines them into a single compound resource {$\thl{1 \tensor 1}$}. After this step, the individual resources are no longer available separately, reflecting the resource-sensitive nature of the system.

This resource-sensitive view of logic provides a foundation for a use in computer science, particularly in the study of concurrency. In the following sections, this perspective is used to motivate the process interpretation underlying \pill.

\subsection{The \texorpdfstring{$\pi$}{pi}-calculus: processes and communication}\label{subsec:processes}
The $\pi$-calculus~\citep{MPW92} is a process calculus for modeling concurrent computation with dynamic communication topology, where channel names themselves can be transmitted, allowing the communication network to evolve during execution. We follow the presentation of~\citet{abs-2106-11818}, which adopts~\citeauthor{W14}'s convention of using square brackets '$[\text{-}]$' for output and round parentheses '$(\text{-})$' for input.

Programs in \pill{} are processes \hl{($\phl{P}$, $\phl{Q}$, $\phl{R}$, $\dots$)}, which communicate over names \hl{($\phl{x}$, $\phl{y}$, $\phl{z}$, $\dots$)} representing session endpoints. Sessions are binary, a discipline enforced by the typing system introduced in~\cref{subsec:types}. Following~\citet{abs-2106-11818}, we assume an infinite set of names with decidable equality. The process terms of \pill{} are defined by the following grammar, reproduced from~\citet{abs-2106-11818} with minor adjustments:

\label{tab:pill-proc-syntax}
\begin{bnftable}% Taken from \cite{abs-2106-11818} with minor adjustments
  {\phl{P}, \phl{Q} \Coloneqq{}}
  {\infer{\choice{x}{P}{Q}}{\clientdup{x}{x'}{P} \pp{} \send{x}{y}{\nil}}}
    \phl{P}, \phl{Q} \Coloneqq{}
    & \send{x}{y}{P}               & output $y$ on $x$ and continue as $P$\\
    \mid{} & \recv{x}{y}{P}       & input $y$ on $x$ and continue as $P$\\
    \mid{} & \close{x}{P}         & output (empty message) on $x$ and continue as $P$\\
    \mid{} & \wait{x}{P}          & input (empty message) on $x$ and continue as $P$ \\
    \mid{} & \res{xy}{P}          & name restriction (cut) \\
    \mid{} & P \pp Q              & parallel composition \\
    \mid{} & \inl{x}{P}           & select left on $x$ and continue as $P$ \\
    \mid{} & \inr{x}{P}           & select right on $x$ and continue as $P$ \\
    \mid{} & \choice{x}{P}{Q}     & offer a binary choice between $P$ or $Q$ on $x$ \\
    \mid{} & \sendtype{x}{A}{P}   & output type $A$ on $x$ and continue as $P$ \\
    \mid{} & \recvtype{x}{X}{P}   & input a type as $X$ on $x$ and continue as $P$ \\
    \mid{} & \server{x}{z_1,\dots,z_n}{P} & server (replicable process) on $x$ depending on servers on $z_1$ \dots $z_n$ \\
    \mid{} & \clientuse{x}{P}     & consume a server on $x$ and continue as $P$ \\
    \mid{} & \clientdup{x}{x'}{P} & duplicate server $x$ as $x'$ in $P$ \\
    \mid{} & \clientdisp{x}{P}    & dispose of a server on $x $\\
    \mid{} & \forward{x}{y}       & link $x$ and $y$ \\
    \mid{} & \nil{}               & terminated process
\end{bnftable}

Term {$\phl{\send{x}{y}{P}}$} allocates a fresh name {$\phl{y}$}, outputs it over {$\phl{x}$}, and proceeds as {$\phl{P}$}. Dually, {$\phl{\recv{x}{y}{P}}$} takes input over {$\phl{x}$}, binding it to {$\phl{y}$} in {$\phl{P}$}. Terms {$\phl{\close{x}{P}}$} and {$\phl{\wait{x}{P}}$} model empty output and input. Restriction {$\phl{\res{xy}{P}}$} connects the two endpoints {$\phl{x}$} and {$\phl{y}$} of {$\phl{P}$} to form a session, where the order of {$\phl{x}$} and {$\phl{y}$} is irrelevant and {$\phl{\res{xy}{P}} \equiv \phl{\res{yx}{P}}$}. Parallel composition {$\phl{P \pp Q}$} runs {$\phl{P}$} and {$\phl{Q}$} concurrently, and {$\phl{\nil}$} is the terminated process, acting as the unit of parallel composition.

\begin{example}\label{ex:cut-unit-proc}
  Consider the process {$\phl{P} \defeq \phl{\res{xz}{(\send{x}{}{\nil} \pp \recv{z}{}{\send{y}{}{\nil}})}}$}. This process creates a private session between the restricted endpoints {$\phl{x}$} and {$\phl{z}$}. The left process, {$\phl{\send{x}{}{\nil}}$}, signals termination on {$\phl{x}$} before terminating, while the right process, {$\phl{\recv{z}{}{\send{y}{}{\nil}}}$}, waits for a termination signal on {$\phl{z}$} before proceeding by sending a termination signal on {$\phl{y}$} and then terminating.
\end{example}

This calculus provides the operational foundation for \pill. In the following section, we introduce the type system that governs how names are used, ensuring that each session endpoint is used exactly according to its protocol.

\subsection{Types and propositions-as-sessions correspondence}\label{subsec:types}
In \pill, session types \hl{$(\thl{A}, \thl{B}, \thl{C}, \dots)$} are linear logic propositions~\citep{CP10, W14, abs-2106-11818}. Each type describes the communication protocol of a channel endpoint, and duality ensures that the two endpoints of every session implement complementary protocols.

The account of session types used in this thesis follows the presentation of~\citet{abs-2106-11818}, which builds on the propositions-as-sessions correspondence developed by~\citet{CLMSW16} and~\citet{W14}. In this correspondence, each connectives of linear logic is interpreted as a communication protocol, where {$\thl{A \tensor B}$} describes sending a value of type {$\thl{A}$} and continuing as {$\thl{B}$}, while its dual {$\thl{A \parr B}$} describes receiving. The units {$\thl{1}$ and $\thl{\bot}$}, again, represent the absence of out and input, respectively. The additive connectives {$\thl{A \oplus B}$} and {$\thl{A \with B}$} capture choice in the sense of selection and offering of alternatives, while the exponentials {$\thl{\bang A}$} and {$\thl{\query A}$} govern replication. The {$\thl{\forall X.A}$} and {$\thl{\exists X.A}$} allow polymorphic session behavior. The type grammar of \pill{} is defined by~\citet{abs-2106-11818} as follows:

\begin{bnftable2col}[\thl] % Taken from \cite{abs-2106-11818} with minor adjustments
    {\thl{A},\thl{B} \Coloneqq {}}
    {A \tensor{} B}{A \tensor{} B}
    \thl{A},\thl{B} \Coloneqq{} {} & A \tensor{} B & send $A$, proceed as $B$ &
    \mid{} {} & A \parr{B} & receive $A$, proceed as $B$ \\
    \mid{} {} & \one{} & empty output, unit for $\tensor$ &
    \mid{} {} & \bot{} & empty input, unit for $\parr$ \\
    \mid{} {} & {A \with{} B} & offer $A$ or $B$ &
    \mid{} {} & {A \oplus{} B} & select $A$ or $B$ \\
    \mid{} {} & {\exists{} X.A} & existential, type output &
    \mid{} {} & {\forall{} X.A} & universal, type input\\
    \mid{} {} & {\query{} A} & client request &
    \mid{} {} & {\bang{} A} & server accept\\
    \mid{} {} & {X} & type variable &
    \mid{} {} & {\dual{X}} & dual of type variable\\
\end{bnftable2col}

Duality is defined structurally on session types by exchanging each connective with its dual and forms an involution, specifically {$\thl{{(A^\bot)}^\bot} = \thl{A}$}. Consequently, the endpoints of a well-typed session are always assigned dual types, ensuring they are compatibility:

\begin{highlight} % Taken from \cite{abs-2106-11818} with minor adjusments
\begin{gather*}

    \qquad
    \thl{\one^\bot} = \thl{\bot}
    \qquad
    \thl{(A \oplus B)}\thl{^\bot} = \thl{A^\bot \with B^\bot}
    \\
    \thl{(\bang A)}\thl{^\bot} = \thl{\query A^\bot}
    \qquad
    \thl{(\exists X.A)}\thl{^\bot} = \thl{\forall X.A^\bot}
    \qquad
    \thl{{(X)}^\bot} = \thl{X^\bot}
\end{gather*}
\end{highlight}

\subsection{Environments, hyperenvironments and judgements}\label{subsec:env-hyper-judge}
Typing environments in \pill{} are organised into two layers. Environments track how individual names are typed, while hyperenvironments track which names are used independently in parallel.

Following the presentation in~\citet{abs-2106-11818}, \emph{environments}~(\hl{$\thl{\Gamma}$, $\thl{\Delta}$, $\thl{\Xi}$, \dots}) are defined as lists allowing exchange, meaning order is irrelevant. They can be written as {$\thl{\Gamma} = \cht{x_1}{A_1}, \dots, \cht{x_n}{A_n}$}, where each {$\phl{x_i}$} is associated to its respective {$\thl{A_i}$}, for $1\leq i \leq n$. Environments can be merged as long as they do not share any names for example assume {$\thl{\Gamma}$} and {$\thl{\Delta}$} do not share any names, then {$\thl{\Gamma, \Delta}$} is the environment containing exactly the entries of {$\thl{\Gamma}$} and {$\thl{\Delta}$} regardless of ordering. Environments act as a partial commutative monoid, using ``$,$'' as sum and the empty environment {$\thl{\emptyseq}$} as unit:

\begin{highlight} % Taken directly from \cite{abs-2106-11818}
\[
\thl{\Gamma, \emptyseq} = \thl{\Gamma}
\qquad
\thl{\Gamma, \Delta} = \thl{\Delta, \Gamma}
\qquad
\thl{(\Gamma, \Delta), \Xi} = \thl{\Gamma, (\Delta , \Xi)}
\]
\end{highlight}

Environments dictate how names are used, but it does not distinguish whether names are used independently or in parallel. That role is handled by  handled by \emph{hyperenvironments} (\hl{$\thl{\hyp{G}}$, $\thl{\hyp{H}}$, $\thl{\hyp{I}}$, \dots}), which are collections of environments joined using the parallel operator `$\pp$'. They can be written as follows {$\thl{\hyp{G}} = \thl{\Gamma_1,\dots, \Gamma_n}$}, where {$\thl{\Gamma_1,\dots, \Gamma_n}$} is a collection of environments. Given {$\thl{\hyp{G}}$} and {$\thl{\hyp{H}}$} having no names in common then {$\thl{\hyp{G} \pp \hyp{H}}$} is the hyperenvironment containing exactly the environments of {$\thl{\hyp{G}}$} and {$\thl{\hyp{H}}$}, ignoring order. Like environments, all names in a hyperenvironment are unique, they can be combined as long as they do not share any names, and they act as a partial commutative monoid using '$\pp$' as sum and $\emptyhyp$ as unit, where $\emptyhyp$ is the hyperenvironment containing no environments:

\begin{highlight} % Taken directly from \cite{abs-2106-11818}
\[
  \thl{\hyp G \pp \emptyhyp} = \thl{\hyp G}
  \qquad
  \thl{\hyp G \pp \hyp H} = \thl{\hyp H \pp \hyp G}
  \qquad
  \thl{(\hyp G \pp \hyp H) \pp \hyp I} = \thl{\hyp G \pp (\hyp H \pp \hyp I)}
\]
\end{highlight}

\emph{Judgements}, written as {$\judge{}{P}{\hyp{G}}$}, states that the process {$\phl{P}$} uses its free names in accordance with {$\thl{\hyp G}$} and can be derived using the inference rules displayed in \cref{fig:pill-typing-rules}.

\emph{Typing Derivations} $(\der{D}, \der{E}, \der{F}, \dots)$ are written as {$\deduce{\judge{}{P}{\hyp G}}{\der D}$}, indicating that $\der{D}$ is a derivation for the judgement.

The multiplicative rules form the core of the system. \Cref{rule:pill-cut} composes two processes in {$\phl{P}$} sharing dual endpoints {$\cht{x}{A}$} and {$\cht{y}{A^\bot}$}, hiding them via restriction. This is the logical equivalent of communication. \Cref{rule:pill-mix} and \cref{rule:pill-mix-0} compose independent processes in parallel and introduce the terminated process, respectively.

\Cref{rule:pill-tensor,rule:pill-parr} type output and input. Note that \cref{rule:pill-tensor} types the sent name {$\phl{y}$} in a \emph{separate} environment from the continuation, reflecting that the two are parallel resources. By contrast, \cref{rule:pill-parr} keeps {$\phl{y}$} and the continuation {$\phl{x}$} in the \emph{same} environment, reflecting their sequential dependency. The unit \cref{rule:pill-one,rule:pill-bot} type empty output and empty input, where \cref{rule:pill-one} requires the continuation to be well-typed in the empty hyperenvironment, meaning {$\phl{P}$} is necessarily semantically equivalent to $\nil$.

The additive rules (\ref{rule:pill-oplus-1},~\ref{rule:pill-oplus-2} and~\ref{rule:pill-with}) type selection and offering of alternative processing paths. Note that \cref{rule:pill-with} requires both branches to be typed in the \emph{same} context {$\thl{\Gamma}$}, reflecting that the choice of branch is made by the other endpoint.

The exponential rules type server replication. The \cref{rule:pill-!} requires all free names except {$\phl{x}$} to be typed using {$\thl{\query}$}, enforcing that a server only depends on other servers. The \cref{rule:pill-?,rule:pill-weaken,rule:pill-contract} allow a client to use, discard, or duplicate a server respectively.

The \cref{rule:pill-axiom} types a link between two dual endpoints, {$\phl{\forward{x}{y}}$}, forwarding all messages sent on {$\phl{x}$} safely to {$\phl{y}$} and vice versa. \Cref{rule:pill-exists} and \cref{rule:pill-forall} type polymorphic communication, where the side condition {$\thl{X \notin \ft(\Gamma)}$} in \cref{rule:pill-forall}, ensures the introduced type variable, {$\thl{X}$}, does not accidentally shadow one already existing in {$\thl{\Gamma}$}.

\begin{example}\label{ex:cut-unit-der}
  \begin{highlight}
    The process from~\Cref{ex:cut-unit-proc} has the typing $\judge{}{\res{zx}{(\recv{z}{}{\send{y}{}{\nil}} \pp \send{x}{}{\nil})}}{\cht{y}{1}}$, as shown by the derivation below:
    \[
      \infer[\ref{rule:pill-cut}]
        {\judge{}{\res{xz}{(\send{x}{}{\nil} \pp \recv{z}{}{\send{y}{}{\nil}})}}{\cht{y}{1}}}
          {\infer[\ref{rule:pill-mix}]
          {\judge{}{\send{x}{}{\nil} \pp \recv{z}{}{\send{y}{}{\nil}}}{\cht{x}{1} \pp \cht{y}{1}, \cht{z}{\bot}}}
          {
            \infer[\ref{rule:pill-one}]{\judge{}{\send{x}{}{\nil}}{\cht {x}{1}}}{\infer[\ref{rule:pill-mix-0}]{\judge{}{\nil}{\emptyhyp}}{}}
            &
            \infer[\ref{rule:pill-bot}]
            {\judge{}{\recv{z}{}{\send{y}{}{\nil}}}{\cht{y}{1}, \cht{z}  {\bot}}}
            {\infer[\ref{rule:pill-one}]{\judge{}{\send{y}{}{\nil}}{\cht {y}{1}}}{\infer[\ref{rule:pill-mix-0}]{\judge{}{\nil}  {\emptyhyp}}{}}}
          }
        }

Note that, for the typing envrionment {$\thl{\cht{x}{1} \pp \cht{y}{1}, \cht{z}{\bot}}$} to align with the premise of~\cref{rule:pill-cut}, we utilise the monoidal properties of environments and hyperenvironments. In particular, using their identity laws, we instantiate the meta-variables of the rule as {$\thl{\hyp{G}} = \thl{\emptyhyp}$} and {$\thl{\Gamma} = \thl{\emptyseq}$}. Under these instantiations, the premise of~\cref{rule:pill-cut}: {$\judge{}{P}{\hyp{G} \pp \Gamma, \cht{x}{A} \pp \Delta, \cht{y}{\dual{A}}}$} can be viewed as {$\thl{\cht{x}{A} \pp \Delta, \cht{y}{\dual{A}}}$}. This effectively instantiates the~\ref{rule:pill-cut} over the dual types {$\thl{A} = \thl{1}$} and {$\thl{\dual{A}} = \thl{\bot}$} on channels {$\phl{x}$} and {$\phl{z}$}, with {$\thl{\Gamma} = \cht{y}{1}$}, while ensuring the restricted endpoints implement dual session behaviours.

\subsection{Operational semantics}\label{subsec:operational-semantics}
The operational semantics of \pill{} are given as a labelled transition system (LTS) defined over \emph{typing derivations}, in which processes evolve by performing actions on their free names. The semantics follow a Structural Operational Semantics (SOS) style presentation and form the basis for the metatheoretic results of the calculus. We will be focusing on the multiplicative fragment for this part, which is given in \cref{fig:mpill-sos}. The full LTS is presented in Figure~2 and Appendix~B.2 of~\citet{abs-2106-11818} .

The operational semantics rely explicitly on the structural equivalence (\cref{rule:pill-alpha}) to rename restricted variables via $\alpha$-equivalence prior to a transition. In paper-based presentations, $\alpha$-equivalence is often handled implicitly through Barendregt's Variable Convention. In a mechanised setting, however, reasoning over named variables requires freshness conditions, capture-avoiding substitution, and explicit renaming lemmas, introducing proof overhead \citep{A05,C12}. As discussed in \cref{sec:binding-architecture}, this motivates the use of a different binding representation for the syntax of \pill{}, one designed to reduce explicit $\alpha$-equivalence reasoning and simplify the treatment of bound variables.

Actions are defined in the set $\ActSet = \{\lclose{x}, \lwait{x}, \lsend{x}{y}, \lrecv{x}{y} \mid x, y \text{ names}\}$, representing empty output, empty input, name output, and name input respectively. These come together with the silent label $\tau$ for internal communication and the parallel composition of labels $l \mid l'$ to form the set of transition labels, defined as $\LblSet = \{\tau, l, (\lsync{l}{l'}) \mid l, l' \in \ActSet,~\is(l) \cap \is(l') = \emptyset\}$. The side condition imposed on the parallel composition of labels exists to ensure two labels do not introduce the same name, which would break linear resource management.

The free and introduced names of labels are defined by $\fs(x[]) = \fs(x()) = \fs(x[y]) = \fs(x(y)) = \{x\}$, $\fs(\tau) = \is(\tau) = \emptyset$, and $\fs(l \mid l') = \fs(l) \cup \fs(l')$, and introduced names by $\is(x[]) = \is(x()) = \emptyset$, $\is(x[y]) = \is(x(y)) = \{y\}$, and $\is(l \mid l') = \is(l) \cup \is(l')$. The parallel label $l \mid l'$ additionally requires $\is(l) \cap \is(l') = \emptyset$, ensuring no two components introduce the same name.

Each logical rule (\ref{rule:pill-one},~\ref{rule:pill-bot},~\ref{rule:pill-tensor},~\ref{rule:pill-parr}) has a corresponding transition axiom. These follow the prefix-continuation pattern {$\phl{\prefixed{\pi}{P}} \lto{\pi} \phl{P}$}, where performing the action $\pi$ leads to the remainder of the process. \Cref{rule:pill-mix-sync} allows for the pairing of concurrent actions via $\lsync{l}{l'}$, which is used to facilitate communication by letting two endpoints connected by a restriction perform compatible actions. When two compatible actions are performed over endpoints connected by a restriction, \cref{rule:pill-cut-one,rule:pill-cut-tensor} simplify the term into an internal $\tau$-transition, modeling the synchronisation of the session.

\subsection{Process semantics and erasure}\label{subsec:process-semantics-erasure}
While the typing derivations of \pill{} dictate the valid interactions within a session, the underlying process terms possess a standard, untyped operational behavior that closely mirrors the classic $\pi$-calculus. To formally relate the typed derivations to their untyped execution, we follow~\citet{abs-2106-11818} and define an erasure function, $\mathit{proc} : \DerSet \to \mathit{Proc}$, which strips away the typing information from a derivation. Recursively, $\mathit{proc}$ maps the head of a typing derivation to the specific process constructor it introduces, continuing structurally onto the process's continuation. For any well-typed \pill{} term, $proc(\hyp{D})$ effectively extracts the pure process term from the derivation's conclusion.

As formulated by~\citet{abs-2106-11818}, the relationship between derivation transitions and process transitions is expressed through erasure. Given the projection $\mathit{proc} : \DerSet \to \mathit{Proc}$, the process LTS enjoys erasure with respect to the derivation LTS when $\mathit{proc}$ is a homomorphism between the two transition systems. By~\citet[Fact~4.6]{abs-2106-11818}, this is equivalent to the relation $\{(\mathit{proc}(\der{D}), \der{D}) \mid \der{D} \in \DerSet\}$ being a strong bisimulation.

\begin{theorem}[Erasure {\citep[Theorem~4.7]{abs-2106-11818}}]\label{thm:operational-correspondence}
The process LTS, $\mlts{p}$, enjoys erasure with respect to the derivation LTS, $\mlts{d}$.
\end{theorem}

Concretely, this correspondence means that, for any typing derivation $\der{D}$ and label $l \in \LblSet$:
\begin{enumerate}
\item if $\der{D} \lto{l} \der{D}'$, then $\mathit{proc}(\der{D}) \lto{l} \mathit{proc}(\der{D}')$; and
\item if $\mathit{proc}(\der{D}) \lto{l} P'$, then there exists a derivation $\der{D}'$ such that $\der{D} \lto{l} \der{D}'$ and $\mathit{proc}(\der{D}') = P'$.
\end{enumerate}

Because well-typed processes lie in the image of $\mathit{proc}$, erasure yields typability preservation:

\begin{corollary}[Typability Preservation {\citep[Corollary~4.8]{abs-2106-11818}}]\label{cor:typability-preservation}
If $P$ is well typed and $P \lto{l} P'$, then $P'$ is well typed.
\end{corollary}

Erasure therefore allows the process LTS to be extracted from the derivation-level semantics while preserving observable transition behaviour. The resulting SOS specification describes process evolution independently of typing derivations.

The process LTS states freshness and name-disjointness as explicit operational side conditions because it describes process evolution independently of typing derivations. For example, synchronising actions must not introduce the same name. This is expressed by the side condition $\is(l) \cap \is(l') = \emptyset$. Although corresponding side conditions in the derivation-level LTS are already enforced for well-typed derivations by the disjointness of hyperenvironment components, they are retained to support erasure to the process LTS~\citep[Remark~3.6]{abs-2106-11818}. The corresponding evolution of typing resources is described by the environment semantics introduced next.

\subsection{Semantics of typing environments}\label{subsec:semantics-environments}
Just as processes evolve through computation, the typing environments that govern them must also evolve to accurately track the state of a session. In \pill, types capture communication protocols. Consequently, the transition rules for typing environments specify exactly which actions are permitted and how the available resources are consumed by those actions. 

Similar to how the erasure function was defined for processes, we again follow~\citet{abs-2106-11818} and define a function $env : \DerSet \to \mathit{Env}$ that maps a valid typing derivation directly to the hyperenvironment in its conclusion (i.e., {$env(\judge{}{P}{\hyp{G}}) = \thl{\hyp{G}}$}). Using this extraction,~\citet{abs-2106-11818} derive a LTS specifically for typing environments ($\mlts{e}$), shown in~\cref{fig:mpill-sos-types}.

In this LTS, observable actions actively consume resources from the environment. For example, if a hyperenvironment contains a waiting channel {$\cht{x}{\bot}$}, performing an input action $\lwait{x}$ will consume this type, removing it from the resulting environment. Conversely, internal communications do not alter the available external resources. This is expressed by the $\tau$-reflexivity axiom, {$\thl{\hyp{G} \mid \Gamma} \lto{\tau} \thl{\hyp{G} \mid \Gamma}$}, which states that any valid hyperenvironment transitions to itself under a silent $\tau$-action.

The rules in \cref{fig:mpill-sos-types} define which transitions are available at the environment level. For a well-typed process, both the process behaviour and resource evolution must step in unison such that whenever the process performs an action, its typing environment performs a corresponding transition. This correspondence is the property of \textbf{session fidelity}. Just as the $\mathit{proc}$ projection extracts the process behaviour of a typed transition, the $\mathit{env}$ projection extracts its corresponding environment evolution.

The following is Corollary~4.10 of~\citet{abs-2106-11818}, stated concretely for a well-typed process:

\begin{corollary}[Session Fidelity for Processes]\label{thm}
Let $\der{D}$ be a typing derivation such that $\mathit{proc}(\der{D}) = \phl{P}$ and $\mathit{env}(\der{D}) = \thl{\hyp{G}}$. If {$\phl{P} \lto{l} \phl{P'}$}, then there exist a hyperenvironment {$\thl{\hyp{G}'}$} and a typing derivation $\der{D}'$ such that $\thl{\hyp{G}} \lto{l} \thl{\hyp{G}'},~\mathit{proc}(\der{D}') = \phl{P'} ~and~ \mathit{env}(\der{D}') = \thl{\hyp{G}'}.$
\end{corollary}

To illustrate session fidelity, consider a particular execution of a well-typed process and the corresponding evolution of its typing hyperenvironment.

\begin{example}[Session fidelity along an execution]
Recall the process derivation from \cref{ex:expanded-cut-unit-execution}, initially typed by the hyperenvironment $\thl{\hyp{G}} = \cht{v}{1}, \cht{w}{\bot} \pp \cht{y}{1}$. Consider the process execution in which the observable input on $w$ is followed by the internal synchronisation on the restricted session, and then by the observable outputs on $y$ and $v$. Session fidelity requires each of these process transitions to be matched by a transition of the typing hyperenvironment:
\begin{highlight}
\[
\begin{aligned}
\cht{v}{1}, \cht{w}{\bot} \pp \cht{y}{1}
&\lto{\lwait{w}} \cht{v}{1} \pp \cht{y}{1} \
&\lto{\tau} \cht{v}{1} \pp \cht{y}{1} \
&\lto{\lclose{y}} \cht{v}{1} \
&\lto{\lclose{v}} \emptyhyp.
\end{aligned}
\]
\end{highlight}

The input action on $w$ consumes the resource {$\cht{w}{\bot}$}. After this transition, the environment LTS allows the output action $\lclose{y}$, since {$\cht{y}{1}$} is already present, although the process cannot yet perform that action. In the process, the corresponding output remains guarded until the internal synchronisation on the restricted session has occurred. This $\tau$-transition does not affect the externally visible resources, but exposes the output on $y$, whose transition consumes {$\cht{y}{1}$}. The final output on $v$ then consumes the remaining external resource.
\end{example}

  \subsection{Managing bound variables}\label{subsec:burden-of-bound-variables}
  Having introduced the operational semantics of \pill{} and the session-fidelity property it supports, we now address the treatment of explicitly representing bound names, scopes, and freshness conditions.

  Several constructs in \pill{} introduce scoped identifiers. Restriction binds pairs of session endpoints, input binds received channel names, polymorphic communication binds type variables, and duplication introduces a fresh channel endpoint in its continuation. These binding constructs occur throughout the process syntax and the labelled transition system.

  For bound channel names, the concrete representative chosen for a binder is semantically irrelevant provided that the binding structure is preserved. For example, renaming the two restricted endpoints of a session does not alter the behaviour of a process. However, a formal account of substitution, transitions, and typing derivations must track names, scopes, and freshness conditions explicitly.

  This principle is expressed by \emph{$\alpha$-equivalence}, which identifies process terms that differ only in their choice of bound channel names. For instance, the following two processes are $\alpha$-equivalent:
  \begin{highlight}
  %
  \[
  \phl{\res{ab}{(\send{a}{}{\nil} \pp \recv{b}{}{\send{x}{}{\nil}})}}
  \aleq
  \phl{\res{zw}{(\send{z}{}{\nil} \pp \recv{w}{}{\send{x}{}{\nil}})}}
  \]
  %
  \end{highlight}
  The operational semantics of \pill{} uses $\alpha$-equivalence through \cref{rule:pill-alpha}, allowing bound names to be changed before a transition when necessary to avoid capture.

  Substitution exposes the same issue. Consider replacing the free name $x$ by $z$ in the right-hand process from the preceding example:
  \begin{highlight}
  \[
    \phl{\res{zw}{(\send{z}{}{\nil} \pp \recv{w}{}{\send{x}{}{\nil}})}} 
  \]
  \end{highlight}
  Here, $z$ is already bound by the restriction, so naively replacing $x$ with $z$ would cause the restriction to capture the newly inserted $z$. 

  Since restriction binds session endpoints as pairs, both the bound name $z$ and $w$ must be $\alpha$-renamed to fresh names, such as to $a$ and $b$, before the substitution proceeds. Generally, any binder capturing a substituted free name must be renamed before substitution occurs. 

  In paper-based presentations, this issue is commonly handled using \emph{Barendregt's variable convention}, under which bound names may be assumed fresh for the free names and other objects relevant to the current argument. This convention keeps paper proofs readable, but it remains an informal meta-level assumption.

  A proof assistant requires each relevant freshness condition and renaming step to be represented and verified explicitly~\citep{A05}. A direct mechanisation using named binders would therefore introduce substantial proof overhead for capture avoidance and reasoning up to $\alpha$-equivalence. The formalisation instead adopts a locally nameless binding architecture, retaining explicit free identifiers while representing bound occurrences by indices. This avoids explicit reasoning up to $\alpha$-equivalence for bound occurrences, while relocating the remaining binder-related obligations to opening, local closure, freshness, and substitution. The following chapter develops this architecture in detail.
